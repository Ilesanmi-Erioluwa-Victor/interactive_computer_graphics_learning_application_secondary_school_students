INTERACTIVE COMPUTER GRAPHICS LEARNING APPLICATION (ICGLA)
================================================================================

================================================================================
1. WHAT THE SOFTWARE IS ABOUT
================================================================================

ICGLA is a full-stack web application (React front-end + Express/MongoDB
back-end) for teaching Computer Graphics to secondary-school students.

There are three types of users:

  STUDENT  - learns from modules and lessons, plays with interactive canvas
             demos (drawing shapes, mixing colours, applying 2D transforms),
             takes auto-graded quizzes, tracks progress, gives feedback.

  TEACHER  - creates classes (with join codes), writes modules/lessons
             (rich text + images/videos + interactive demos), builds quizzes,
             monitors each student's progress, replies to feedback.

  ADMIN    - approves teacher accounts, manages all users and classes,
             reads all feedback, views system-wide reports.

Key features built so far:

  - Account system with JWT login, registration (student needs a class code,
    teacher needs admin approval), password reset by email.
  - Syllabus: modules containing lessons.
  - Lessons: rich-text content, media attachments, optional embedded
    interactive HTML5 canvas demos.
  - Quizzes: single-choice, multiple-choice and true/false questions; time
    limit, attempt limit, pass mark; graded entirely on the server using an
    all-or-nothing rule per question; full answer review afterwards.
  - Progress tracking: lessons marked complete, per-module completion %,
    time spent, recent quiz scores, "continue learning" suggestion, and a
    full "My Progress" page (stats, module bars, quiz attempt history).
  - Classes: teacher creates a class and gets a join code for students.
    Students join at registration OR later from their own "My Classes" page.
    Teachers can rename a class at any time.
  - Class-targeted content: a module can be limited to specific classes
    ("Visible to classes" picker). Empty = all the teacher's classes
    (default). The rule applies to modules, lessons, quizzes and the
    "new lesson" notification.
  - Quiz status badges: the student syllabus marks quizzes already taken
    ("Taken 1x - Best 100% - Passed"); the teacher module list shows a
    draft/published badge so an unpublished quiz is obvious.
  - Notifications: in-app bell (new lesson, quiz graded, feedback replied,
    account events) plus email via the Brevo transactional email API.
  - Feedback: students can leave feedback on a lesson or quiz; teachers and
    admins can read and reply.
  - Admin reports: charts of users, attempts, pass rates, etc.
  - Media uploads: images/videos go to Cloudinary if configured, otherwise
    they are stored locally under server/uploads/ and served from the API.

3. TESTING AS A STUDENT
================================================================================

3.1 REGISTER A NEW STUDENT
  - Log out if needed. Click "Create account" / Register.
  - Choose the STUDENT role.
  - Fill in name, email, password. Enter a class code (e.g. ZS24FV).
  - Submit. You should be taken to the student dashboard.
  - Check the email you registered with - a "Welcome to ICGLA" email should
    arrive (sent via Brevo). If it does not, look at the server console; any
    Brevo failure is printed there as [EMAIL] ... .

3.2 LOGIN (existing student)
  - Log in with teststudent3@example.com / password123.

3.3 DASHBOARD
  - Verify the 4 stat cards (syllabus %, lessons completed, time spent,
    recent quizzes).
  - Verify "Progress by module" chart and "Module details" bars.
  - "Continue learning" should take you to a lesson (or to the syllabus if
    you have not started anything).

3.4 SYLLABUS (Modules -> Lessons)
  - Open "Syllabus" from the side menu.
  - Click a module to expand its lessons.
  - Click a lesson -> it opens the lesson viewer with the lesson content.

3.5 INTERACTIVE CANVAS DEMOS (important!)
  For any lesson that has an embedded demo, test all three types:
  - Shape drawing   : choose a tool (Line / Rectangle / Circle / Polygon),
                      drag on the canvas, clear the canvas. Works with mouse
                      AND touch (mobile).
  - Colour mixer    : drag the RGB sliders; the preview colour and its
                      hex value should update live.
  - Transformations : adjust translate / rotate / scale sliders and watch
                      the shape move/rotate/resize on the canvas; try
                      switching the shape.
  Report any canvas that does not resize or draw correctly.

3.6 QUIZZES
  - From the syllabus, open a quiz (or from a module quiz card).
  - On the syllabus, a quiz you have already attempted shows a badge next to
    its title: "Taken 1x - Best 100% - Passed" (green = passed, amber = not
    passed). Quizzes not yet attempted have no badge.
  - Read the intro screen (questions, time limit, pass mark, attempts left,
    grading rule).
  - Click "Start quiz".
  - Answer questions: single-choice uses radio buttons, multiple-choice uses
    checkboxes. Navigate with Previous/Next.
  - IMPORTANT: try intentionally leaving at least one question unanswered
    and submitting - your percentage must be based on ALL questions, not just
    the ones you answered.
  - Let the timer run down on a timed quiz - it should auto-submit.
  - After submit you see your score %, pass/fail, and a full answer review
    with correct answers and explanations.
  - On a multiple-choice question verify the all-or-nothing rule: selecting
    the exact correct set gives full marks; missing one option gives ZERO
    for that question.
  - Re-taking: attempt limit should be enforced (a 403 message appears when
    attempts run out). Pass/fail "Try again" button appears only on failure.

3.7 PROGRESS
  - Open "My Progress".
  - Verify the stat cards (overall completion %, lessons completed, modules
    completed, time spent) and the per-module progress bars.
  - Verify the "Quiz attempts" table lists each attempt with score,
    Passed/Failed and date. Attempts on archived/deleted quizzes must NOT
    appear (the dashboard "Recent quiz scores" links only to live quizzes).

3.8 MY CLASSES (join a class after registering)
  - Open "My Classes" from the side menu.
  - Your joined classes are listed with their codes and student counts.
  - Enter a teacher's code in the "Join a class" box and click Join class.
    Joining a class makes that teacher's published modules/quizzes appear in
    your syllabus (refresh the syllabus to pick them up). Duplicate join is
    rejected.

3.9 FEEDBACK
  - After finishing a quiz (or on a lesson page) use the feedback form to
    send a comment. Check the notification bell for a reply later.

3.10 NOTIFICATIONS
  - The bell icon in the top bar shows notifications (new lesson published,
    quiz graded, feedback replied). Mark all read works.

3.11 ACCOUNT / LOGOUT
  - Log out and log back in. The session should persist while the browser
    has the token; expired/invalid tokens should send you to login.

4. TESTING AS A TEACHER
================================================================================

4.1 REGISTER A NEW TEACHER
  - Log out. Register with the TEACHER role (no class code needed).
  - You should be told your account awaits admin approval.
  - The account cannot do anything until an admin approves it (test this
    too - login should be restricted until approved).

4.2 LOGIN AS EXISTING TEACHER
  - testteacher@example.com / password123 (already approved).

4.3 CREATE A CLASS
  - Open "My Classes". Create a class, e.g. "SS1 Graphics".
  - The app shows a join code. Use that code in an incognito window to
    register a new student (or use ZS24FV for the existing class).
  - Open the class roster to see students in the class.
  - Use the "Rename" button on a class card to change its name; the students'
    profile class name updates to match.

4.4 CREATE A MODULE + LESSON
  - Open "Lessons & Modules". Create a module (title, description).
  - "Visible to classes" picker:
      * Leave "All my classes" (default) - every class you teach sees it.
      * Or tick one or more of your classes - ONLY students in those classes
        will see the module, its lessons and its quiz. Each module card shows
        its current visibility ("All my classes" or the class names).
  - Use the "Edit" button on a module card to change its title, description,
    visibility or published state at any time.
  - Add a lesson to it:
      * Title, estimated minutes, rich-text body (use the toolbar - bold,
        lists, images, etc.)
      * Add a media attachment (image/video/diagram) - test the upload
        (falls back to local storage if Cloudinary is not configured).
      * Set the interactive demo type: None / Shape drawing / Colour mixer /
        Transformation. Set any available config (e.g. which shapes).
      * Order: reorder lessons with up/down controls if provided.
  - IMPORTANT: publish the lesson. Unpublished lessons must NOT be visible
    to students.
  - Verify students receive a "new lesson" notification (only students in the
    targeted classes get it when the module is class-limited).

4.5 CREATE A QUIZ
  - Open "Lessons & Modules". Each module has a "+ Quiz" button (becomes
    "Edit Quiz" once a quiz exists); the module is pre-selected for you.
  - Fill in title, pass mark %, max attempts, time limit (optional), shuffle
    option and the "Published (visible to students)" checkbox. Save settings.
  - Click "+ Add question" to open the question form. Add questions of each
    type: single-choice, multiple-choice, true/false. Set points and an
    explanation for each. Save each question, then "Save all questions".
  - Use "Edit" on an existing question to change it.
  - Publish the quiz (tick Published + Save settings). The module list badge
    turns green ("Quiz published"); until then it is amber ("Quiz draft - not
    visible to students").
  - Verify students cannot open it before it is published.
  - Edit a question and check existing attempts still display correctly.

4.6 VIEW STUDENT PROGRESS
  - Open "Student Progress". Select a student and a module to see lessons
    completed, quiz attempts and scores.
  - Verify the drill-down shows attempt details and correct answers.

4.7 FEEDBACK INBOX
  - Open "Feedback Inbox". Reply to a student's feedback. The student should
    get a notification (and email) of your reply.

4.8 NOTIFICATIONS
  - Verify you see "teacher approved" and any system notifications.

6. GENERAL THINGS TO CHECK IN EVERY SCREEN
================================================================================

  - Responsive layout: resize the browser to a narrow phone width (375px),
    a tablet (768px) and a desktop (1280px). Sidebar should collapse to a
    hamburger/menu button; tables should scroll horizontally, not break the
    page.
  - Lesson content should never overflow: long words wrap, code blocks and
    tables scroll horizontally within the card.
  - Keyboard navigation: Tab through quiz options and buttons; the quiz
    options should be selectable with the keyboard (radio/checkbox).
  - All buttons that start an action should give feedback (toast messages).
  - Invalid forms should show clear validation errors.
  - Refresh the page mid-quiz / mid-lesson - it should fail gracefully
    (go back to syllabus with a friendly message), not hang.
  - Empty states: create a fresh student in a class with no content yet and
    confirm pages show "no content" messages rather than errors.

7. KNOWN TESTING NOTES / AREAS TO SCRUTINISE FOR BUGS
================================================================================

  - Quiz percentage on skipped questions (must count unanswered questions
    in the denominator).  -> server/utils/gradeQuiz.js
  - All-or-nothing multi-choice grading (exact set match). -> same file
  - Timer auto-submit on quizzes.
  - Attempt limit enforcement (maxAttempts).
  - Email sending (Brevo): every send prints to the server console on
    failure; missing textContent was fixed to auto-derive from HTML.
  - Media uploads: if Cloudinary env vars are set they upload there;
    otherwise local /uploads. Verify uploaded images actually display in
    lessons.
  - Publish/unpublish gates: unpublished lessons/quizzes must be invisible
    to students.
  - Soft-deletes: modules/lessons/quizzes are archived, not hard-deleted, so
    student history is preserved.
  - Teacher approval gate: pending teacher cannot log in to do work.
  - Class codes are app-generated; a made-up code must fail with
    "Invalid class code" at registration AND at the student "Join a class"
    form.
  - Class-targeted modules: a student must NOT see a module whose target
    classes exclude theirs; after joining the right class it must appear.
    (server/controllers/lessonController.js and quizController.js)
  - Quiz visibility: an unpublished quiz must be invisible to students; the
    teacher module list badge must reflect draft/published state.
  - Stale quiz links: "Recent quiz scores" and "My Progress" must not list
    attempts on archived/deleted quizzes (server filters them out).
  - Quiz editor: "+ Add question" must open the question form (regression
    guard - this used to be broken) and "Save all questions" persists them.
  - Time spent is recorded best-effort and capped server-side; the dashboard
    shows minutes (e.g. "12 min") under an hour.

9. ENVIRONMENT CONFIGURATION (server/.env)
================================================================================

  MONGO_URI          MongoDB Atlas connection string (set)
  JWT_SECRET         Secret for signing login tokens
  CLOUDINARY_*       Optional; media uploads fall back to local storage
  BREVO_API_KEY      Brevo transactional email API key (set)
  BREVO_SENDER_EMAIL Verified sender address in Brevo (set)
  CLIENT_URL         http://localhost:5173 (used for password reset links)
  API_BASE_URL       http://localhost:5000 (used by media fallback URLs)
  ADMIN_EMAIL / ADMIN_PASSWORD / ADMIN_NAME  used by "npm run seed"

  Never commit .env files - they are ignored by .gitignore (root and
  client/ and server/ all cover .env). A .env.example documents the
  variables.
